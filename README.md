# Kinopoisk Sentiment Analysis

Классификация тональности русскоязычных отзывов на фильмы: от исследования данных и классического TF-IDF baseline до дообучения RuBERT.

Проект решает задачу трёхклассовой классификации: `bad`, `neutral` и `good`. Метки взяты из категорий отзывов Кинопоиска, а не размечены вручную.

## Что есть в проекте

- Парсер ссылок на фильмы и отзывы с сохранением состояния.
- Воспроизводимая очистка CSV с проверкой колонок и меток.
- EDA: баланс классов, длины отзывов, дубликаты и качество данных.
- Два baseline: мажоритарный класс и TF-IDF + Logistic Regression.
- Дообучение `cointegrated/rubert-tiny2` с весами классов и выбором лучшего чекпоинта по macro F1.
- Матрица ошибок, отчёт по классам и примеры inference.

## Данные

Исходный датасет: [Kinopoisk Reviews на Kaggle](https://www.kaggle.com/datasets/halssara/kinopoisk-reviews).

| Версия | Строк | Колонки | Комментарий |
|---|---:|---|---|
| Исходная | 33 863 | `film_name`, `user_review`, `review_type` | 3 полных дубликата; `film_name` целиком равно `Unknown` |
| Очищенная | 33 860 | `user_review`, `review_type` | Дубликаты и неинформативная колонка удалены |

Распределение очищенного датасета:

| Метка | Отзывов | Доля |
|---|---:|---:|
| `good` | 22 570 | 66.66% |
| `neutral` | 6 284 | 18.56% |
| `bad` | 5 006 | 14.78% |

Для воспроизведения очистки поместите исходный CSV в `data/data.csv` и выполните:

```bash
python prepare_dataset.py data/data.csv data/kinopoisk_reviews_clean.csv
```

Скрипт удаляет `film_name` только если во всём файле находится единственное значение `Unknown`. Если в новых данных появятся настоящие названия фильмов, колонка сохранится.

## Результаты

| Модель | Accuracy | Macro F1 | Weighted F1 |
|---|---:|---:|---:|
| Majority class | 0.667 | 0.267 | 0.533 |
| TF-IDF + Logistic Regression | 0.783 | 0.654 | 0.768 |
| RuBERT-tiny2, первый эксперимент | 0.760 | 0.690 | 0.770 |

Baseline выполнен на зафиксированном стратифицированном разбиении с `SEED = 42`. Метрики RuBERT сохранены из первого исторического запуска со случайным незафиксированным разбиением, поэтому **строки таблицы нельзя считать строгим сравнением моделей**. Теперь оба ноутбука после одинаковой очистки используют один вызов `sklearn.train_test_split` для индексов строк, а очищенный CSV выбирается в приоритете перед исходным. Для обновлённых метрик RuBERT необходимо перезапустить на GPU.

Главная сложность обеих моделей — класс `neutral`. В baseline его F1 составляет 0.400, в первом RuBERT-эксперименте — 0.49.

## Быстрый запуск

Рекомендуется Python 3.12.

```bash
git clone https://github.com/Halssara/nlp_kinopoisk_reviews.git
cd nlp_kinopoisk_reviews
python -m venv .venv
```

Активация в Windows Git Bash:

```bash
source .venv/Scripts/activate
```

Активация в Linux/macOS:

```bash
source .venv/bin/activate
```

Установка зависимостей и запуск JupyterLab:

```bash
python -m pip install -r requirements.txt
jupyter lab
```

Датасет на Kaggle приватный. Для локального запуска скачайте CSV и поместите его в `data/`. Каталог `data/` исключён из Git. Ноутбуки поддерживают как стандартный путь `/kaggle/input/kinopoisk-reviews/`, так и путь приватного датасета `/kaggle/input/datasets/halssara/kinopoisk-reviews/`.

## Ноутбуки

### `kinopoisk-eda-baseline.ipynb`

[Открыть опубликованный ноутбук на Kaggle](https://www.kaggle.com/code/halssara/kinopoisk-sentiment-eda-and-tf-idf-baseline). Он полностью выполнен на CPU: загрузка и очистка данных, EDA, стратифицированное разбиение, мажоритарный baseline, TF-IDF + Logistic Regression, метрики, матрица ошибок, интерпретация коэффициентов и примеры предсказаний.

### `kinopoisk-bert.ipynb`

Дообучение RuBERT-tiny2 на GPU: токенизация, веса классов, частичная разморозка модели, выбор чекпоинта по macro F1, отчёт по классам, сохранение модели и inference.

Сохранённые выводы относятся к первому эксперименту. Код подготовлен для нового воспроизводимого запуска, но обновлённые результаты ещё не получены.

## Повторный сбор данных

Для парсеров нужен Chrome. Selenium Manager автоматически подбирает совместимый ChromeDriver.

```bash
python get_urls.py
python parser.py
```

- `get_urls.py` собирает ссылки с первых пяти страниц популярных фильмов и дополняет `to_process.json`, сохраняя ранее собранные URL.
- `parser.py` обрабатывает положительные, нейтральные и отрицательные отзывы и сохраняет результат в `data.csv`.
- `processed_urls.json` не позволяет повторно обрабатывать завершённые фильмы.

Сбор занимает время из-за намеренных задержек. Перед запуском проверьте актуальные условия использования Кинопоиска и допустимость автоматического сбора. При изменении вёрстки сайта селекторы могут потребовать обновления.

## Ограничения

- В исходных данных нет названий фильмов, поэтому невозможно сделать групповое разбиение по фильмам.
- Отзывы одного фильма могут оказаться одновременно в train и test.
- Метки источника субъективны; граница между `neutral` и остальными классами не всегда однозначна.
- Длинные рецензии усекаются при токенизации BERT.
- Условия использования и права на тексты отзывов необходимо проверять отдельно; лицензия на код не заменяет разрешение на распространение пользовательских текстов.
